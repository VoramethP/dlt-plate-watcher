# ADR-0006 · แยก "เลขที่ขนส่งกันไว้ประมูล" ออกจากเลขที่แจ้งให้ไปกดจอง โดยใช้กฎจากประกาศ ไม่ถามระบบขนส่ง

- สถานะ: ยอมรับ · 2026-09-21
- เกี่ยวข้อง: ADR-0001 (แจ้งเตือนอย่างเดียว) · ADR-0003 (ไม่แตะ reserve.dlt.go.th)

## บริบท

ผู้ใช้รายงาน (21 ก.ย. 2569) ว่า **เลขที่ bot แจ้งมาส่วนใหญ่กดจองไม่ได้** เพราะขนส่งกันไว้ประมูล

สาเหตุตรงไปตรงมา: กรมการขนส่งทางบกกันหมายเลข "ซึ่งเป็นที่ต้องการหรือเป็นที่นิยมของประชาชน"
**301 หมายเลขต่อหนึ่งหมวดอักษร** ไปประมูลที่ tabienrod.com ที่เหลือจึงเข้าระบบจองออนไลน์
นิยามของ "เลขสวย" ในประกาศ (เลขตอง เลขเรียง เลขคู่ เลขหลักพัน …) **คือนิยามเดียวกับ pattern ที่ผู้ใช้ตั้งไว้ใน wishlist**
ยิ่ง bot คัดว่าสวย ยิ่งมีโอกาสเป็นเลขที่จองไม่ได้ — การ์ด 🎯 จึงกลายเป็นงานให้ผู้ใช้ไปนั่งลองกดแล้วผิดหวัง

## ทางเลือกที่พิจารณา

1. **ถามระบบขนส่งว่าเลขนี้ว่างไหม** — ตัดทิ้งทันที ผิด ADR-0001/0003 และไม่เสนอทางอ้อมใด ๆ
2. **ดึงรายการเลขประมูลจาก tabienrod.com ตอนทำงาน** — ยังเป็นการเพิ่มโดเมนที่โปรแกรมแตะ (ADR-0003 อนุญาตแค่
   drive.google.com + discord.com) และรายการก็ไม่ได้เปลี่ยนรายสัปดาห์ ไม่คุ้มกับความเสี่ยง
3. **ฝังกฎที่ประกาศไว้เป็นไฟล์ข้อมูลในรีโป** ← เลือกข้อนี้

## การตัดสินใจ

- เก็บรายการ 301 หมายเลขไว้ใน **`auction-rules.json`** (รูปแบบเดียวกับ `numerology.json`: มี `sources` กำกับ)
  สร้างด้วย `npm run gen:auction` ซึ่งอ่าน **ตารางแนบท้ายประกาศฯ** แล้วจัดกลุ่มตามรูปเลข
  สคริปต์จะล้มถ้าได้ไม่ครบ 301 หรือมีเลขที่จัดกลุ่มไม่ได้ — กันอ่าน PDF ผิดแบบเงียบ ๆ
- **`gen-auction-rules.ts` เป็นสคริปต์ตอนพัฒนา ไม่ใช่โค้ดที่ bot เรียกตอนทำงาน** — ADR-0003 คุม runtime
  ตอน bot ทำงานอ่านแต่ไฟล์ JSON ในรีโป
- เลขที่เข้ากฎ **ไม่ถูกลบทิ้ง แต่ย้ายไปอยู่ช่อง 🔨 ของตัวเอง** ในการ์ด 🎯 และปุ่ม 📋 พร้อมชื่อกลุ่มตามประกาศ
  ผู้ใช้ยังเห็นว่าเลขนั้นมีอยู่ และรู้ว่าต้องไปประมูล ไม่ใช่รอกดตอน 10:00
- **วันไหนที่ตรงเงื่อนไขแต่เป็นเลขประมูลล้วน = ไม่แจ้งเตือน** (รวมถึงไม่ปิง 09:50) เพราะไม่มีอะไรให้ผู้ใช้ทำ
  — ยังดูย้อนได้จากปุ่ม 🎯 / 📋 ที่ผู้ใช้กดเอง
- ประกาศไม่ได้ครอบคลุมทุกกรณี (ขนส่งจังหวัดกันเลขเพิ่มเองได้ · เลขที่ประมูลแล้วไม่มีคนเอาจะถูกปล่อยกลับเข้าระบบจอง)
  จึงมี **ช่อง 🔨 ในปุ่ม 🔢** ให้ผู้ใช้ทำเครื่องหมายเลขที่ "ลองกดแล้วจองไม่ได้" เอง (เก็บเป็น `kind='auction'` ในตาราง wishlist)
  ของจริงที่ผู้ใช้เจอทับกฎในไฟล์เสมอ

## ผลที่ตามมา

- pattern ยอดนิยมอย่าง "เลขตอง" (`1111`) และ "เลขคู่สลับ" (`6464`) **เข้าข่ายประมูลทั้งกลุ่ม** → หลังเปลี่ยน
  การ์ดของผู้ใช้จะบางลงมาก นั่นคือความจริงที่ถูกบอกเร็วขึ้น ไม่ใช่ฟีเจอร์หาย
- ยังไม่เช็คว่าเลขถูกคนอื่นจองไปหรือยัง (ADR-0001) — 🔨 ตอบแค่ "เลขนี้ไม่ได้อยู่ในระบบจองออนไลน์ตั้งแต่แรก"
- ถ้าขนส่งแก้ประกาศ ต้องรัน `npm run gen:auction` ใหม่แล้ว commit ไฟล์ — ไม่มีการอัปเดตอัตโนมัติโดยตั้งใจ
- รถทั้งสามประเภทที่ bot รองรับ (รย.1/2/3) ใช้ชุดเลขเดียวกัน ตรวจแล้วตอนสร้างไฟล์ ถ้าวันหนึ่งไม่เท่ากัน สคริปต์จะล้ม
  พร้อมข้อความว่าต้องแยกไฟล์ตามประเภทรถ
