# ADR-0003 · ให้ผู้ใช้ใส่ file id ของตารางเอง แทนการดึงหน้าเว็บขนส่งด้วย User-Agent ปลอม

- สถานะ: ยอมรับ · 2026-09-18
- เกี่ยวข้อง: ADR-0001

## บริบท

หน้า `reserve.dlt.go.th/reserve/v2/?menu=schedule` ฝังตารางเป็น PDF จาก Google Drive ผ่าน `<iframe>`
แผนแรกคือดึงหน้านี้เพื่อหา file id อัตโนมัติ แต่จากการทดสอบ (2026-09-18) WAF ของขนส่ง (F5) ตอบ
"Request Rejected" ให้ทุก User-Agent ที่ไม่ใช่ browser รวมถึงรูปแบบบอตสุภาพมาตรฐาน
`Mozilla/5.0 (compatible; dlt-plate-watcher/0.1; +url)` มีเพียง `Mozilla/5.0` เปล่า ๆ ที่ผ่าน

## การตัดสินใจ

- **ไม่ปลอม User-Agent เป็น browser** เพื่อผ่าน WAF — นั่นคือการหลบมาตรการควบคุมการเข้าถึงของเจ้าของระบบ
  แม้จะทำง่ายและเป็นที่นิยมก็ตาม
- โปรแกรมจึง**ไม่แตะ reserve.dlt.go.th เลย** แตะแค่ Google Drive ซึ่งเป็นไฟล์ที่ขนส่งตั้งใจแชร์สาธารณะ
- ผู้ใช้เปิดหน้าตารางในเบราว์เซอร์ตัวเอง คัดลอกลิงก์ iframe (หรือ HTML ทั้งก้อน) มาใส่ `scheduleFileId` ใน config
  โปรแกรมแกะ id ให้เอง
- ฟีเจอร์ "เช็คว่าหน้าจองเปิดหรือยัง" ถูกตัดออก เพราะต้องดึงหน้าจอง แทนด้วยการปิงตามเวลา 10:00 ที่ประกาศบนหน้าเว็บ

## หลักฐานว่าภาระของผู้ใช้น่าจะน้อย

ไฟล์บน Drive ชื่อ `number_v2.pdf` และ `Last-Modified` ตรงกับเช้าวันจันทร์ต้นสัปดาห์ของตาราง
บ่งชี้ว่าขนส่ง**อัปโหลดทับไฟล์เดิม**ทุกสัปดาห์ file id จึงน่าจะคงที่ ยังไม่ยืนยัน 100% จนกว่าจะเห็นสัปดาห์ถัดไป
จึงมี stale detection: ถ้าทุกวันในตารางผ่านไปแล้วแต่ไฟล์ไม่เปลี่ยน โปรแกรมจะเตือนให้ไปเอา id ใหม่

## ผลที่ตามมา

- ใช้ `Last-Modified` ของ Drive เป็น "เวอร์ชัน" ของตาราง แทนการเทียบ file id
- ถ้าวันหนึ่งขนส่งเปิด API หรือ feed ที่ตั้งใจให้เครื่องอ่าน ให้ย้ายไปใช้ทันทีและทบทวน ADR นี้
